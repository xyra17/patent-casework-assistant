# 辅助分析与验收

系统提供22个业务入口。两版技术文档对比、上传交底找参考和公开技术资料检索直接进入现有任务流程；系统先给出有依据的内容和初步分析，同时说明缺口与原因。

| 场景 | 可交付内容 | 需要明确的限制 |
| --- | --- | --- |
| 两版技术文档对比 | 基准/对比顺序、程序文字对照、两侧原句、位置与文件版本；有依据的影响分析 | 文字替换不能直接证明机制替换或等价；解析失败、扫描图形与未比较章节明确列出 |
| 上传交底找参考 | 上传技术要素、候选案号、双侧原文、匹配依据、相似点与差异 | 检索排名不是专业最相近或可替代的证明；没有可靠候选时说明已检索范围和缺口 |
| 公开技术资料检索 | 真实网页来源、原始链接、标题、摘要与有据解释 | 未取得网页或关键片段时明确说明；推断与原文分开，不伪造最新版本或检索成功 |

## 验收依据

1. **事实与来源**：原句、案号、条件、版本和定位须能对应。错误引用、跨案拼接、伪造数值及无依据的确定性结论不发布。
2. **回答覆盖**：逐项核对用户要求，区分已完成、部分完成和缺失。说明原因及需补充材料；不能用“已说明限制”冒充必答项已经完成。
3. **部分结果可用性**：保留能核对的原文、程序对照和数据，不因另一项未完成就删除。审查未完成时，保守发布逐字匹配的引文或来源数据单元格；简短引文须是完整来源分句，不能从较大数值中截取。
4. **专业分析**：给出依据、前提和不确定性；必要时提示专业复核。复核不应阻止交付已取得的资料与有据分析，免责声明也不能使错误结论通过。

文字变化与机制断言分别核对；否定判断不能被当成肯定结论拦截，免责声明也不能抵消另一处无依据的机制断言。缺口说明同样属于需核对的事实：已取得的定义不能说成未取得，取得定义也不代表默认值、实现或性能已经核实。

程序校验、真实任务运行与独立业务评价分别记录。整体 `INCOMPLETE` 可以含可用的子结果；它不是完整任务通过。恢复入口、通过单元测试或返回部分内容都不能换算成新的业务通过率。历史冻结题目、gold、评分及原始记录不改写。

## 知识库状态

案件原件目录与公司文档索引分别检测。案件目录就绪而公司文档为空时，案件资料仍可用；目录大量文件缺失、扫描失败或公司索引错误会显示具体原因。系统保留已有解析记录，待核对后恢复原件或重新同步，不自动把空目录当成全库删除。

## 验收失败如何归因

| 层面 | 判断依据 | 处理方式 |
| --- | --- | --- |
| 程序设计与输出 | 原始输入、工具返回、渲染前后正文、文件版本和可复现检查 | 可程序检查的字数上限、字符位置、重复引文先做离线正反例；专业语义仍单独审查 |
| 资料与检索 | 本次实际取得的全文或片段、截断范围、来源定位 | 先查是否读错、漏读或截断，再判断材料不足；检索未命中不能证明原件或全网没有 |
| 评判标准 | 用户实际要求、正文、证据及逐项审查理由 | 不新增用户没要求的条件；系统S编号不是原件自带编号。失败审查是待复核意见，不自动认定答案错误 |
| 模型输出与能力 | 在资料充分、程序正确、标准明确条件下的具体错误 | 区分事实错误、推理缺口与表达问题；单次失败、预算触顶或调用失败不能证明能力上限 |
| 专业人工判断 | 可追溯证据、模型初步解释、前提与未解决问题 | 提供具体核对项，由专业人员形成最终判断；未记录确认人和结论时不能显示已人工确认 |

调用超时、服务额度、访问限制及有明确标记的调用预算分别记录；未能识别的异常保留“原因尚未分类”。调用未完成不等于内容错误。历史运行若只有笼统错误，须结合独立调用记录归因，不能靠改文案改写旧事实。

网页检索的`focus`按关注术语选取供应商实际返回的原文，优先保留对应Markdown章节及其参数列表。有网页正文时仅从正文选段，供应商摘要不混入同一原句证据；只有摘要时明确标注尚未取得正文。摘录保存字符跨度；可保存的原始返回文本按哈希保留在线程内。它不是完整网页保证，供应商没有返回的内容仍需补取。保密和共享检索次数限制持续生效。

## 证据与模型判断

三个分析入口在有待核对内容时生成核对材料：原文证据、原始模型草稿、程序拦截项、自动审查意见及专业核对项。草稿默认折叠并标记未确认，原文入口沿用来源面板。自动审查意见不能冒充客观事实，模型草稿不能冒充已核验结论。

材料绑定最终交付正文和证据快照哈希，原始草稿须从同一线程的哈希产物读取；正文或来源变化后旧材料失效。材料不会改变`VERIFIED/REVIEW_REQUIRED/INCOMPLETE`，也不会制造人工确认记录。未完成任务仍保留对应状态。

## 低成本复核

先复用已保存的`raw.json`、候选正文和工具返回，检查程序及评价口径。可使用：

```bash
.venv/bin/python scripts/replay_assistance_diagnostics.py 保存记录目录 新派生输出目录
```

输入目录包含三个入口各自的`raw.json`和`candidate-round-N.md`。脚本不调用模型、不改原始记录或历史评分；输出派生正文、程序检查与核对材料，并验证输入文件哈希未变化。离线回放能确认已知程序行为，不能证明修复后的模型会正确理解要求，也不能产生新业务通过率。
