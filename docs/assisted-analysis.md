# 辅助分析与验收

系统提供22个业务入口。两版技术文档对比、上传交底找参考和公开技术资料检索直接进入现有任务流程；系统先给出有依据的内容和初步分析，同时说明缺口与原因。

| 场景 | 可交付内容 | 需要明确的限制 |
| --- | --- | --- |
| 两版技术文档对比 | 基准/对比顺序、程序文字对照、两侧原句、位置与文件版本；有依据的影响分析 | 文字替换不能直接证明机制替换或等价；解析失败、扫描图形与未比较章节明确列出 |
| 上传交底找参考 | 上传技术要素、候选案号、双侧原文、匹配依据、相似点与差异 | 检索排名不是专业最相近或可替代的证明；没有可靠候选时说明已检索范围和缺口 |
| 公开技术资料检索 | 真实网页来源、原始链接、标题、摘要与有据解释 | 未取得网页或关键片段时明确说明；推断与原文分开，不伪造最新版本或检索成功 |

## 验收依据

1. **事实与来源**：原句、案号、条件、版本和定位须能对应。错误引用、跨案拼接、伪造数值及无依据的确定性结论不发布。
2. **回答覆盖**：逐项核对用户要求，区分已完成、部分完成和缺失。说明原因及需补充材料；不能用“已说明限制”冒充必答项已经完成。
3. **部分结果可用性**：保留能核对的原文、程序对照和数据，不因另一项未完成就删除。审查未完成时，保守发布逐字匹配的引文或来源数据单元格；简短引文须是完整来源分句，不能从较大数值中截取。
4. **专业分析**：给出依据、前提和不确定性；必要时提示专业复核。复核不应阻止交付已取得的资料与有据分析，免责声明也不能使错误结论通过。

程序校验、真实任务运行与独立业务评价分别记录。整体 `INCOMPLETE` 可以含可用的子结果；它不是完整任务通过。恢复入口、通过单元测试或返回部分内容都不能换算成新的业务通过率。历史冻结题目、gold、评分及原始记录不改写。

## 知识库状态

案件原件目录与公司文档索引分别检测。案件目录就绪而公司文档为空时，案件资料仍可用；目录大量文件缺失、扫描失败或公司索引错误会显示具体原因。系统保留已有解析记录，待核对后恢复原件或重新同步，不自动把空目录当成全库删除。
