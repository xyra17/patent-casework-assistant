# 对话与记忆

在任务结果中选择“对话与记忆”，可继续追问、指定参考轮次、切换话题或回看保存的回答。来源与筛选口径可从每轮回答下方打开；“会话记忆”抽屉可查看各层加载量、调入的轮次和升降级记录。

例如：先列出客户甲的案件，再问“这些案件中只看林澄负责的”，或“把负责人改成周行，保持其他条件”。较早的记录可按案号、关键词及中文双字词自动检索；明确回指旧任务时，可据此定位旧对象，动态办理信息仍重新查询。

## 加载层级

| 层级 | 默认注入上限 | 加载内容 |
| --- | --- | --- |
| 热层 | 2048 Token | 当前目标、本轮问题、筛选条件、案件范围及澄清内容必须完整携带；余量预载已升温的历史摘要 |
| 近期层 | 1024 Token | 最近三条符合来源权限的记录摘要，按预算整条装入 |
| 冷层 | 2048 Token | 完整旧轮次保存在 SQLite；先查倒排索引，再读取最多六个匹配候选的相关片段，按预算装入 |

三层序列化后的模型输入载荷合计不超过5632 Token。计量使用 `cl100k_base`，是估算值，不是模型账单 Token；系统提示与工具定义另受执行上下文预算约束。配置见 `.env.example` 的 `MEMORY_*_TOKENS`。

同一记录累计两次已接受的命中，且最近四轮内用过，可进入热层；热历史最多三条，当前任务需要更多空间时旧摘要让位。超过四轮未用降至近期层，超过八轮未用且不在最近三轮中则进入冷层。浏览页面、预览、模型要求澄清或过期请求均不增加命中次数。

必载内容超限会要求缩小范围或新开话题，不会截断案号、条件或问题。追问提案未通过校验时最多校正一次，校正输入也受预算约束；仍无法明确则要求补充，不更新命中次数。完整回答与来源快照不因压缩、升降级或检索而改写。历史片段只用于定位对象与上下文，不作为当前状态的证据，也不会自动成为长期规则。

## 适用范围

自动召回限定当前会话和本次获准来源，普通追问只搜索当前话题。新话题清空继承范围；之后明确说“之前”“上次”等回指旧任务，或选择参考轮次时，可以检索更早话题。只有被明确选中的旧记录参与对象绑定，不会因关键词相似就自动继承旧条件。其他会话不会自动混入，移入回收站后不可检索，永久删除时同步清理派生索引与加载记录。

长期规则由用户确认后保存，按任务相关性审核应用，可以编辑、停用；本次明确要求优先。拟稿不会自动保存，追问也不会扩大数据源权限。

## 运行与验证

```bash
.venv/bin/python scripts/test_backend_offline.py tests.test_memory_cache tests.test_conversation tests.test_clarification -v
.venv/bin/python scripts/verify_memory_cache.py --data-dir /tmp/casework-memory-demo
.venv/bin/python scripts/verify_memory_cache.py --data-dir /tmp/casework-memory-demo --serve --port 8770
```

访问 `http://localhost:8770`，打开保存的会话和“会话记忆”抽屉，可查看真实缓存加载记录。固定构造输入的 `checks.json` 包含预算、召回、升降级、持久化与快照哈希检查；该演示不调用模型，不能作为自然语言理解准确率或真实业务效果的证明。重新验收使用新目录，`--serve` 只回放已保存的结果。

需要验证配置的真实模型时，可在新目录运行 `scripts/verify_memory_cache.py --data-dir /tmp/casework-memory-live --live-resolution`。此选项会调用模型并可能产生费用，只检查构造追问的对象绑定与预算，不执行案件查询。
