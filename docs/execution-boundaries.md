# 任务执行：固定流程与 Agent

任务由同一个 Python 后端组织。程序按完整需求选择执行策略，再使用固定业务执行器或 DeepAgents；四种策略共享来源设置、工具和会话存储。

## 执行策略

| 策略 | 执行方式 | 典型任务 |
| --- | --- | --- |
| `direct` | 完整句式匹配后，一次读取同一案件的指定字段并输出 | 负责人、阶段、单个或多个期限 |
| `workflow` | 按预定动作读取、计算和组织结果 | 期限排查、月度统计、固定会前卡 |
| `conditional` | 固定检索起步，再根据返回结果筛选、补查或澄清 | 相似案件查找、辅助分案 |
| `agent` | 模型根据中间结果选择后续工具与行动 | 附件理解、跨来源比较、开放分析与报告 |

四种策略不是四套服务，也不是每题依次经过的四层。任务模式和工具调用次数不能单独决定执行策略。直接查询要求完整匹配整个问句；额外分析、附件、复杂规则或超出固定能力的要求会进入相应规划路径。

入口见 [`casework/routing.py`](../casework/routing.py)、[`casework/execution_policy.py`](../casework/execution_policy.py) 和 [`agent/main_agent.py`](../agent/main_agent.py)。

## 固定任务

- **字段查询**：同一案件的单字段或多字段一起读取，分别保留缺失、冲突和来源。
- **完整清单**：程序处理筛选、分页和数量；超过读取上限时标明未完整。
- **期限排查**：程序确定基准日、计划节点、分组与未知值。
- **月度统计**：按实际日期和客户范围计算数量及明细，表格由程序生成。
- **会前卡**：固定读取案件信息、技术原文与同案材料包，整理负责人、三个计划期限、最近会议待补和材料范围。
- **相似案件与辅助分案**：先检索和筛选，再依据资料缺口决定补查或请求补充；分案结果由业务人员决定。

满足完整契约和程序检查条件的字段、清单、期限和月报可以直接返回；其他固定任务仍可能调用模型进行理解、整理或审查。开放任务保留动态规划能力。实现见 [`casework/workflow.py`](../casework/workflow.py)。

## 按案材料收集

[`collect_case_materials`](../casework/materials.py) 按明确案号读取当前登记文件清单与已发布正文，保留文件版本、位置、解析警告和读取状态。默认正文预算为 80000 字符；达到预算或尚未解析的材料单独标记。读取全部已发布正文不表示原文件中的扫描页和图形都已理解。

固定资料读取保持同一 SQLite 快照下的顺序执行。相互独立、已取得资料的相关性分类批次可以有界并行，默认上限为 2；实现见 [`casework/parallel.py`](../casework/parallel.py)。

## 任务内资料复用

[`casework/read_cache.py`](../casework/read_cache.py) 为同一任务的固定执行、主智能体和子智能体复用案件读取。缓存绑定工具参数、来源设置、已发布数据版本与来源记录；失败和等待用户补充的结果不缓存。缓存最多 32 项、总计 8 MB，任务结束清理，不跨任务共享。

## 动态执行与停止

主智能体可以直接使用获准的案件工具。需要独立上下文或专业工具时，再调用相应子智能体。来源设置是执行上限，进入 Agent 不会扩大访问范围。

结果需要调整时，在剩余轮次、工具和时间预算内处理具体步骤。重复调用没有新增资料或处理进展时停止；缺关键条件时等待用户补充，资料不足时保留已完成内容和缺口。

前端通过 WebSocket 接收已持久化事件，并通过 REST 恢复断线后的显示；后端进程重启后的自动续跑不在此机制范围内。

## 配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `CASEWORK_PROGRAM_CONTRACTS` | `1` | 启用完整句式匹配的程序契约；设 `0` 使用语义提取路径 |
| `CASEWORK_PARALLEL_REVIEW` | `2` | 独立相关性分类的并发上限；设 `1` 顺序执行 |
