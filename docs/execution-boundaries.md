# 固定业务流程与 Agent 多步查询的边界

以下描述依据公开仓库中的任务路由、业务契约和执行代码。具体任务的执行路径以对应运行记录为准。

## 1. 用什么标准区分

固定流程中，程序预先定义可执行动作、参数范围、查询组合、计算规则与输出。模型从自然语言中提取参数，执行后还会参与相应审查，因此固定流程也会调用大模型。

Agent 流程中，主智能体及按需装配的子智能体在任务目标、来源权限和预算内，依据已取得的结果决定后续查询、检索词、需要读取的材料与解释方式。任务可以只需一步，也可以形成“查询结果决定下一次查询”的多步链路；进入 Agent 流程本身不证明发生了多步查询或多个子智能体协作。

| 容易混淆的概念 | 实际含义 |
| --- | --- |
| 自动识别／快速问答／数据分析／报告 | 用户选择的任务形式，不直接等于执行引擎 |
| 多数据源 | 数据库、案卷知识检索、普通知识库、公开网络或附件的组合；固定分案也会结合两类来源 |
| 多次工具调用 | 固定 `case_brief` 会分别查案件信息和正文；次数不能证明由模型动态规划 |
| Agent 动态查询 | 由模型根据中间结果选择后续动作，实际行为需从本轮工具参数与返回核对 |
| 知识库多跳检索 | 知识检索工具内部的有限补查，属于检索层，需与主智能体步骤分开描述 |
| 反思轮次 | 对上一轮交付进行检查与修正；一轮也可以有多次查询 |

## 2. 固定流程的当前能力

| 动作 | 可覆盖任务 | 来源 |
| --- | --- | --- |
| `summary` | 当前接入范围内的案件总数、在办数、已核实交局数与状态未知数 | `db_query` |
| `archive` | 根据技术描述或完整案号找正文／绘图附件，返回支持范围内的原文承办人、技术片段和指定数量 | `knowledge` |
| `cases` | 案件信息、所限／客户送审／向局提交期限；同一节点未来 14 天、逾期、未知等受支持筛选；单案交局归月核对 | `db_query` |
| `case_brief` | 一个完整案号的案件信息与技术正文联合核对 | `db_query` + `knowledge` |
| `monthly` | 明确月份范围内实际收案与已核实实际交局计数、两月案量增减；可做单客户过滤 | `db_query` |
| `meetings` | 根据客户和实际 IPR 查逐场会议及实际参会同事，支持已有客户区分规则 | `db_query` |
| `recommend` | 以现有技术经历、领域、在办量和三期限规则推荐候选；缺口时进入补充确认 | `db_query` + `knowledge` |

用户明确排除技术适配、仅按负荷选人，或在补充确认中选择仅展示负荷时，推荐动作有专门的负荷模式，只需数据库来源。它们分别表示负荷排序或负荷展示，不能冒充技术适配推荐。

动作按逐项需求交集编译：每个正向要求和执行约束都必须被保留，参数必须符合动作的 schema，实体要绑定目录中的实际对象。额外要求不能藏进自由文本参数，也不能因为“主体能做”就丢弃剩余条件。

注意：“两个月多了或少了多少件”已有程序差值计算；“按代理师分组计算增长率、均值或工时”超出该固定月报契约。案件工作台支持的页面操作与自然语言固定契约的参数范围也不完全相同。

## 3. 路由顺序与停止边界

1. 记录用户目标、任务模式、附件、长期规则、交付要求与来源权限上限。
2. 常规任务中，只有无附件、无会改变业务约束的长期规则、无 PDF 要求，且存在启用的部门根目录时，才尝试部门固定契约。仅含术语别名的规则可随任务进入固定流程；受支持的 Markdown 报告要求也可由契约覆盖。用户在补充确认中选择只看负荷有单独处理分支。
3. 模型提取需求和参数，程序校验实体、能力范围与完整条件。格式或参数无效可做一次有界修正；真实超出能力的任务转完整 Agent 规划。
4. 必要来源必须在允许范围内。固定任务必要来源被禁时直接阻断；进入 Agent 也不能扩大权限或用公开网络替代缺失的内部事实。
5. 执行后作对应事实及交付校验。固定流程同一快照下的确定性结果若仍未通过且没有可处理的新缺口，会停止；动态 Agent 按剩余预算定向修正。

| 情况 | 当前处理 | 任务示例 |
| --- | --- | --- |
| 需求在契约范围内 | 执行固定动作并校验 | “找两份与这项机制相关的旧案，引用技术原句。” |
| 有契约外的分析或交付 | 交完整 Agent 规划，保留全部要求 | “读新交底，查旧案比较技术差异，生成 PDF。” |
| 固定任务必要来源被禁 | 阻断并提示调整范围／来源 | “不查数据库，但要给当前在办量与三期限负荷。” |
| 字段冲突或实际日期未知 | 保留冲突／未知，不替用户选值 | “核对 DEMO-2026-024 初稿期限，来源冲突要列明。” |
| 分案缺关键技术依据 | 请用户补充机制、案号或附件，或由用户明确选择负荷模式 | “新案涉及没有可核对旧案的技术，适合给谁？” |
| 校验失败、预算耗尽或审查不可用 | 保存部分结果和未达标项 | 不能靠自由改写、隐藏重试或更换事实取得通过 |

Agent 仍需使用受控工具并接受业务复算；自动分案、写入共享盘、法定期限或专利法律结论不因转入 Agent 而获得执行授权或正确性保证。
