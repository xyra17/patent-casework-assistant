# 任务数据源选择

实现日期：2026-10-27。

## 使用方式

提交区“数据源”按钮可选择业务数据库、知识库和联网检索，无须每次在问题中写“不联网、不查知识库”等控制语句。默认允许业务数据库和知识库，关闭联网；模型在允许范围内按任务选择必要来源，允许不等于强制检索。

- 内部来源选择保存在当前浏览器，后续新任务沿用；全部关闭也是有效选择，仅使用当前问题和会话附件。
- 联网只为本次新任务开启，提交后及刷新后关闭，不作为浏览器长期偏好。已有任务重跑沿用该次保存的设置，用户可以在“任务理解 → 数据源权限”调整后重跑。
- 问题中明确的禁止要求继续生效。例如勾选两个内部来源，但问题要求“只查业务数据库”，知识库仍不可用；问题要求联网也不能自行开启未勾选的联网权限。
- 来源不够时保留缺口，说明需调整设置或补充资料；不自动越权，不把缺资料伪装成已核实结果。
- 受部署保密策略限制或未配置检索服务时，联网选项不可用并显示原因。配置状态无法确认时前端暂不开放选项，实际访问仍由后端检查。

来源选择控制 Agent 的检索工具，不代表新增用户身份、数据库写权限或解除外发保护，也不改变当前模型端点是否允许的部署策略。会话附件仍按原有权限和会话隔离规则访问。

## API 与持久化

`POST /api/task` 新增 `allowed_sources` 数组，取值仅为 `db_query`、`knowledge`、`web_search`，最多三个。字段省略时为 `["db_query", "knowledge"]`；空数组表示不开放这些检索工具；显式 null 或未知值拒绝。任务文本和来源设置分别传输，来源设置不拼进原始问题。

`GET /api/task-sources` 返回默认内部来源与联网服务是否可选、不可选原因。它只检查本地配置与部署策略，不探测外部服务，也不保证第三方运行时一定可用。

SQLite 的 `runs.allowed_sources_json` 保存本次选择；执行归档保留此前选择，详情 API 返回 `allowed_sources`。历史执行缺少字段时显示“未记录”，不能倒推其当时权限；旧任务重跑默认仅允许内部来源。迁移只新增可空字段，不修改旧执行快照。

## 程序边界

1. `api/task_sources.py` 的独立 ContextVar 保存用户选择上限，与模型的 TaskPlan 分离。服务从保存的任务配置建立上下文；直接调用 `run_deep_agent` 也默认关闭联网。任务结束恢复上下文，async 任务和线程池互相隔离。
2. 路由和规划合并来源上限与任务文字限制，形成 `forbidden_sources`，移除不允许的 `required_sources`。长期规则只能调整理解，不能扩大上限。相关提示进入规划与执行上下文，计划事件也保存上限供核对。
3. 证据缺口路由只能在上限内补开来源。`api/source_policy.configure` 每次独立合并上限与保密模式限制，即便上层计划错误也不能扩大实际工具权限。
4. 主/子智能体只装配当前计划开放的助手；网络、知识库、数据库工具及连接函数在 IO 前再次检查。原有保密模式与外发保护继续优先执行。

快捷模板把来源限制放入 `allowed_sources` 元数据；欢迎页和输入区同时填入问题与来源设置，正文保留具体业务要求。

## 界面依据与验证

沿用现有任务设置栏、Popover 与复选框，遵循 refero-design 的具体状态文案和状态色规则：常驻仅一个紧凑入口，完整选择按需展开；联网开启时强调状态，关闭时显示“联网关”。不增加每次提交必经的确认弹窗。

受控测试覆盖默认/空选项、参数校验、SQLite与归档恢复、并发/线程隔离、任务与界面限制求交集、规划及工具权限不能扩大、受限工具在 IO 前拒绝、保密模式优先和浏览器偏好不恢复联网。前端还验证请求字段独立传输。规则测试与界面操作验证不证明模型语义判断永远正确。
